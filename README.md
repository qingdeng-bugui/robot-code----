# STM32 麦轮小车与气球视觉戳击

本仓库包含小车底盘固件、循迹与边界保护、红外遥控、云台/戳针舵机控制，以及运行在 PC/树莓派上的气球视觉程序。主控为 STM32G474RCT6（LQFP64），固件工程使用 Keil MDK-ARM。

> 接线说明按固件中的 MCU 引脚定义整理。仓库没有给出电机驱动板、循迹模块、红外接收头和舵机的具体型号或连接器编号；连接外设板时应按下文的信号名和外设数据手册核对，不能把 MCU GPIO 直接接到电机或大电流负载。

## 功能概览

- 四轮麦克纳姆底盘：前进/后退、横移、原地旋转；四路编码器反馈和 PID 轮速闭环。
- 循迹：通过 UART 接收 8 路传感器数据，执行黑线跟随和终点判断。
- 场内保护：利用循迹模块数据识别边界，进行短时后退/横移/转向。
- 气球视觉：视觉主机运行 YOLO 跟踪，向 STM32 发送目标横向误差和可戳状态；STM32 控制云台、接近和戳针。
- 红外遥控：启动循迹、戳球流程或组合流程，也可在主循环中发出简单的底盘/舵机动作。
- OLED：通过 PA8/PA9 软件 I2C 初始化 SSD1306 类显示屏；当前启动流程只初始化并清屏。

## MCU 接线

### 串口与人机模块

UART 为 115200、8 数据位、无校验、1 停止位（8N1）。UART 外设与 STM32 之间使用兼容的 3.3 V TTL 电平；TX/RX 交叉连接，并连接共同地。不要把 RS-232 电平或未经确认的 5 V GPIO 直接接入 STM32。

| 用途 | STM32 引脚 | 外设端连接 | 备注 |
| --- | --- | --- | --- |
| 视觉 UART1 TX | PC4 / USART1_TX | 视觉主机串口 RX | 主控向视觉端发送 `START` |
| 视觉 UART1 RX | PC5 / USART1_RX | 视觉主机串口 TX | 接收 `dx,can_hit`、`none`、`ok` 及带 `red` 字段的扩展帧 |
| 循迹 UART2 TX | PA2 / USART2_TX | 循迹模块 UART RX | 发送启停命令 |
| 循迹 UART2 RX | PA3 / USART2_RX | 循迹模块 UART TX | 接收 8 路传感器帧 |
| OLED SCL | PA8 | OLED SCL | GPIO 开漏模拟 I2C |
| OLED SDA | PA9 | OLED SDA | GPIO 开漏模拟 I2C |
| 红外接收信号 | PB15 / TIM15_CH2 | 红外接收头 OUT | 使用下降沿捕获 NEC 脉冲 |
| SWDIO | PA13 | ST-Link SWDIO | 调试/下载 |
| SWCLK | PA14 | ST-Link SWCLK | 调试/下载 |

OLED 的 SCL/SDA 配置为开漏且没有启用 MCU 内部上拉。确认 OLED 模块自身有上拉电阻；否则需按模块电压和总线规范补充外部上拉。OLED 的供电电压、红外接收头供电以及循迹模块供电按对应模块规格选择。

### 电机驱动器

每个电机需要一组 PWM/使能信号和两路方向信号。将下表信号接到电机驱动器对应通道的 PWM/EN、IN1、IN2；电机接驱动器输出端，电机电源接驱动器电源端。电机电流不能经过 STM32。驱动器逻辑地、STM32 GND、电源地必须共地。

| 轮位/代码编号 | PWM | 方向信号 1 | 方向信号 2 |
| --- | --- | --- | --- |
| 左前 / Motor 1 | PA5 / TIM2_CH1 | PD2 | PC11 |
| 右前 / Motor 2 | PA1 / TIM2_CH2 | PB6 | PB4 |
| 左后 / Motor 3 | PB10 / TIM2_CH3 | PB5 | PB3 |
| 右后 / Motor 4 | PB11 / TIM2_CH4 | PB9 | PB7 |

固件将方向脚设成相反电平实现正反转；速度为零时该通道两方向脚均置高、PWM 置零。若安装后某个轮子的正方向相反，应检查电机线序或对应方向定义，不要仅靠交换 PWM 引脚修正。

### 编码器

每路编码器的 A/B 相接到对应定时器通道。下表中的 A/B 是代码所用通道名称；实际编码器供电和输出电平请按编码器/电机驱动板规格确认，STM32 输入需满足 3.3 V 电平要求。

| 轮位/代码编号 | A 相 | B 相 | 定时器 |
| --- | --- | --- | --- |
| 左前 / Encoder 1 | PA11 / TIM4_CH1 | PA12 / TIM4_CH2 | TIM4 编码器模式 |
| 右前 / Encoder 2 | PA0 / TIM5_CH1 | PC12 / TIM5_CH2 | TIM5 编码器模式 |
| 左后 / Encoder 3 | PC6 / TIM8_CH1 | PC7 / TIM8_CH2 | TIM8 编码器模式 |
| 右后 / Encoder 4 | PB2 / TIM20_CH1 | PC2 / TIM20_CH2 | TIM20 编码器模式 |

编码器信号地需要与控制板共地。若速度反馈方向不对，应检查 A/B 相次序、电机方向和 `Encoder.c` 的计数符号。

### 舵机与戳针

| 功能 | STM32 信号 | 代码调用 | 逻辑角度 |
| --- | --- | --- | --- |
| 戳针机构（Servo 1） | PB0 / TIM3_CH3 | `Servo_SetAngle(1, angle)` | `87°` 收针，`135°` 出针 |
| 云台（Servo 2） | PB1 / TIM3_CH4 | `Servo_SetAngle(2, angle)` | `168°` 为车体正前方；搜索范围约 `80°` 至 `258°` |
| 预留舵机（Servo 3） | PA4 / TIM3_CH2 | `Servo_SetAngle(3, angle)` | 预留接口 |

表中是 PWM 信号线，不包含舵机电源线。舵机通常需要独立、足够电流的稳压电源；按舵机规格选择电压，将舵机电源地与 STM32 GND 共地。首次上电前先断开连杆或针机构，确认角度方向和机械限位，避免舵机堵转或钢针误弹出。

### 外设连接注意事项

- MCU 的电机 PWM/方向脚只连接电机驱动器逻辑输入，不直接驱动电机。
- 视觉主机和循迹模块 UART 均需交叉 TX/RX；两端波特率必须一致。
- 连接 USB-TTL 转换器时确认是 3.3 V 逻辑，并接 GND；不要把转换器的 VCC 与外设电源盲目并接。
- 先断开钢针或将针头做防护，再单独验证舵机、底盘和视觉流程。
- 引脚复用以 `robot code.ioc` 和 `Core/Src` 初始化代码为准；修改引脚后要同步更新 CubeMX 配置与硬件接线。

## 固件构建与下载

1. 安装 Keil MDK-ARM，并准备工程所需的 STM32G4 Device Family Pack、CMSIS 和 HAL 组件。
2. 打开 `MDK-ARM/robot code.uvprojx`。
3. 选择工程配置后执行 Build/Rebuild；检查 Build Output 中的错误和警告。
4. 使用 ST-Link，通过 SWDIO（PA13）、SWCLK（PA14）和 GND 连接目标板，下载生成的固件。
5. `.ioc` 可用 STM32CubeMX 打开查看或修改外设。重新生成代码前确认保留 `USER CODE` 区域，并检查 `Hardware` 下的自定义驱动没有被替换。

固件启动顺序大致为：HAL/时钟和外设初始化，启动四路 PWM、编码器、舵机和红外捕获；TIM1 周期中断执行四路速度 PID；主循环调用 `IR_work()` 等待红外命令。自动流程运行时会进入阻塞式任务函数。

## 视觉程序

### 环境准备

在运行视觉程序的 PC/树莓派上安装 Python 依赖：

```bash
python -m pip install opencv-python ultralytics pyserial
```

`pyserial` 仅在需要串口通信时使用。连接摄像头和 STM32 的 USB-TTL/UART 接口后，编辑 `视觉/mypredict_detect_realtime_v2.py` 开头配置：

```python
MODEL_PATH = r"E:\qiqiu3\best_mixed_ncnn_model"
CAMERA_DEVICE = 0
SERIAL_ENABLED = False
SERIAL_DEVICE = "/dev/ttyUSB0"
SERIAL_BAUDRATE = 115200
WAIT_FOR_START = False
```

- 将 `MODEL_PATH` 改为本机可用且与安装的 Ultralytics 版本兼容的模型文件/导出目录。仓库不包含模型权重。
- `CAMERA_DEVICE` 是摄像头索引；默认采集分辨率为 640×480，目标检测置信度阈值为 0.50，推理尺寸为 320。
- 要向 STM32 输出视觉帧，必须把 `SERIAL_ENABLED` 设为 `True`，并将 `SERIAL_DEVICE` 改成实际串口。例如 Windows 可使用 `COM5`，Linux 常见为 `/dev/ttyUSB0`；以设备管理器或 `ls /dev/tty*` 查到的端口为准。
- 视觉端和 STM32 的串口均为 115200 8N1。串口接线见上表，特别注意 TX/RX 交叉和共地。
- `WAIT_FOR_START=True` 时程序等待 STM32 发来 `START` 后开始检测；默认 `False` 会启动后立即检测。主控进入戳球流程时会发送 `START`。

运行：

```bash
python "视觉/mypredict_detect_realtime_v2.py"
```

脚本默认显示 `Balloon Tracking` 窗口，按 `q` 退出。串口未启用时仍可查看检测画面，但不会向底盘发送目标数据。

### 视觉到主控的协议

目标帧/搜索帧均为 ASCII 文本，以换行符结束（`START` 例外，不带换行符）：

| 帧内容 | 含义 |
| --- | --- |
| `dx,can_hit\n`，例如 `42,1\n` | 目标横向中心误差和可戳标志；`can_hit` 为 `0` 或 `1` |
| `dx,can_hit,red,red_dx\n`，例如 `25,0,red,-15\n` | 同上，同时报告红球横向误差 |
| `none\n` | 当前未检测到可攻击目标 |
| `none,red,red_dx\n`，例如 `none,red,-15\n` | 没有可攻击目标，但画面里有红球 |
| `ok\n` | 目标在丢失后重新锁定的通知 |

`dx = 目标框中心 X - 画面中心 X`，正值表示目标位于画面中心右侧，负值表示位于左侧。视觉脚本优先沿用上一目标的跟踪 ID，否则选择面积最大的非红色类别目标（当前红色排除类别 ID 为 3）。跟踪用的中心、尺寸和面积经过中值/EMA 平滑；可戳距离门限使用当前帧的原始框高。重新捕获目标时重置滤波器。

**`can_hit=1` 的含义**：视觉判定已进入可戳窗口，但钢针即使全伸到 135°，针尖离气球表面仍有约 3cm。因此主控收到 `1` 后不是“出针即完成”，而是：停车 → 最多 150ms 把针轴收正 → 出针 → 沿针轴以 6cm/s 推进（上限 1.2s）→ 目标从画面消失（视觉判定已戳破）立即停车收针 → 后退脱离。

当前 `can_hit` 判定要求：横向偏差在画面中心 `±90 px` 内、目标框高度占画面高度 `50%` 至 `100%`，并连续满足 2 帧。退出判定有轻微高度回滞。相机安装位置、焦距、目标实际大小会影响距离判断，需在实车上校准 `MIN_HEIGHT_RATIO`、`MAX_HEIGHT_RATIO` 和横向窗口。

主控也会通过同一 UART1 向视觉端发送 `START`。视觉程序读取启动命令的线程与视频检测线程分开；启用 UART 通信时，两端都可以收发。

## 控制流程说明

### 代码入口和模块职责

- `main.c`：初始化 HAL、时钟、TIM、USART、GPIO；启动电机、编码器、舵机、OLED、红外和 100 Hz PID 中断；主循环调用 `IR_work()`。
- `ir_nec.c`：TIM15_CH2（PB15）捕获 NEC 红外信号，验证命令字及反码后分发动作。
- `track.c`：通过 UART2 向循迹板发送 `$0,1,0#`（启用）或 `$0,0,0#`（停用），并解析 `$A,x1:...,x2:...,...,x8:...#` 数据帧。
- `Function.c::Tack_line()`：对 8 路传感器数值阈值化后计算黑线偏差、调节左右轮目标速度，并在终点确认后停车。
- `Function.c::Keep_In()`：把 8 路传感器数据用于场地边界保护，在循迹或场内移动时执行短时避边动作。
- `Function.c::Hit_Balloons()`：每 5 ms 消费最新视觉行，执行云台扫描、目标跟踪、戳击和场地覆盖掉头。
- `Motor.c::Car_Move(vx, vy, omega)`：麦轮逆运动学。`vx` 向前为正，`vy` 向左为正，`omega` 逆时针为正，线速度单位 cm/s、角速度单位 °/s。轮距/轮半径参数在 `Motor.h`。
- `PID.c`、`Encoder.c`：TIM1 周期中断每 10 ms 读取编码器速度并更新四路 PID 输出；PID 输出转换成 PWM 占空比及方向。
- `Servo.c`：TIM3 产生舵机 PWM；Servo 2 的逻辑角度经映射后输出到 PWM。

### 戳球状态机

`Hit_Balloons()` 中的 `hit_state` 当前含义如下：

| 状态 | 动作 |
| --- | --- |
| `HIT_IDLE`(0) | 普通目标跟踪；收到 `can_hit=1` 后停车转入 `HIT_ALIGN` |
| `HIT_ALIGN`(1) | 车体静止，云台以 0.1°/px、死区 6px、单帧 ≤6° 收正针轴；`|dx|≤30px` 或满 150ms 立即出针 |
| `HIT_EXTEND`(2) | 戳针伸至 135°，等待 150ms 走完舵机行程 |
| `HIT_PUSH`(3) | 保持出针：先 6cm/s 直推 0.4s（约 2.4cm），随后每 380ms 一次「收针 87° 180ms → 出针 135° 200ms」的反复戳，期间以 3cm/s 沿针轴继续前进；云台以 0.05°/px、死区 20px、单帧 ≤2° 继续收针尖 |
| `HIT_RETRACT`(4) | 停止推进、收针至 87°，静止等待 200ms |
| `HIT_BACKOFF`(5) | 以 6cm/s 后退 550ms，然后返回跟踪/搜索 |

推进期间收到 `none`（视觉判定目标已扎破）会立即停车收针；推进+反复戳满 2.0s（总行程约 7cm）目标仍未消失也会收针后退（说明没扎破，随后会按新的视觉帧再接近一次）。`none,red,dx` 与 `dx,can_hit,red,dx` 只用于红球避让信息，不改变戳击时序。

视觉超时、云台机械限位、场地边线和掉头扫描参数集中在 `Hardware/Function.c` 文件顶部。修改速度/时间前应先核对单位，并在抬起车轮、移除针头的条件下验证方向。

无目标时云台在约 80°–258° 间每 60 ms 步进扫描，底盘以 10 cm/s 慢速前进搜索。云台限位脱困、边界后退和场地掉头均由计时状态控制；掉头开始阶段较快，后半段减速并恢复云台扫描。

## 红外遥控命令

红外命令为通过 NEC 校验后的命令字，遥控器按键与命令字的对应关系取决于遥控器型号。当前固件映射如下：

| 命令字 | 动作 |
| --- | --- |
| `0x45` | 戳针舵机收回到 87° |
| `0x46` | 戳针舵机伸出到 135° |
| `0x47` | 进入循迹流程 `Tack_line()` |
| `0x44` | 进入视觉戳球流程 `Hit_Balloons()` |
| `0x43` | 云台回到逻辑角度 168° |
| `0x08` / `0x5A` | 左移 / 右移 |
| `0x18` / `0x52` | 前进 / 后退 |
| `0x16` / `0x0D` | 逆时针 / 顺时针旋转 |
| `0x1C` | 下发零速度停车 |
| `0x40` 后接 `0x15` | 执行组合流程：先循迹，再进入视觉戳球 |

`Tack_line()`、`Hit_Balloons()` 和 `All_functions()` 是阻塞式流程；它们运行期间主循环不会继续调用 `IR_work()`。因此当前固件没有在这些自动流程中持续处理红外急停命令。实际测试请准备独立的电机电源切断/急停方式，不要把遥控 `0x1C` 当作自动流程中的安全急停。

## 常见调试检查

1. **视觉窗口有框但小车不跟踪**：检查 `SERIAL_ENABLED`、串口设备名、USB-TTL 端口、PC4/PC5 TX/RX 交叉、115200 8N1 和共地；同时确认模型路径有效。
2. **视觉脚本报找不到模型**：检查 `MODEL_PATH` 指向本机模型文件或导出目录；权重不包含在仓库中。
3. **循迹传感器数据全零/不更新**：检查循迹模块电源、UART2 交叉接线和模块帧格式；固件只解析以 `$A,` 开头、`#` 结尾的 8 通道帧。
4. **车轮方向或底盘运动方向错误**：核对电机通道和方向脚接线、轮子安装方向、编码器相序及 `Car_Move` 的坐标约定。
5. **轮速抖动或数值不准**：检查编码器供电/相位，并按实际电机编码器修改 `Encoder.c` 的 PPR 和 `Motor.h` 的轮半径/轮距。
6. **戳针过早触球或够不到**：先校准云台/相机轴线和舵机机械角度，再调整 `Hardware/Function.c` 的 `VISUAL_HIT_PUSH_SPEED`（直推速度）、`VISUAL_HIT_JAB_SPEED`（反复戳时的前进速度）与 `VISUAL_HIT_PUSH_MAX_MS`（总时限）；视觉可戳距离由 Python 中的目标框高度窗口决定。
7. **反复戳没劲/行程看起来只走一半**：`VISUAL_HIT_JAB_IN_MS`、`VISUAL_HIT_JAB_OUT_MS` 是每个相位的保持时间，若舵机行程时间超过它，针只走半程就反向——把它们同时加大（例如 250/250，周期 500ms）让舵机走完整行程；反过来若出现车身顶到球，先减小 `VISUAL_HIT_JAB_SPEED` 或 `VISUAL_HIT_PUSH_MAX_MS`。
8. **OLED 不亮**：检查供电、GND、PA8/PA9、模块 I2C 地址/控制器兼容性及上拉电阻。

## 安全提示

首次调试请架空车轮、断开戳针或给针头加保护，并使用限流电源。确认电机方向、编码器方向、云台角度范围和视觉误差方向之后，再在空旷场地逐步测试自动流程。确保 MCU、UART 外设、编码器和舵机信号侧共地；电机/舵机电源应按负载规格单独设计，并保留物理急停。
